# @pasabot/mod-connectors (W13)

Connector catalogue, installs and the OAuth2 PKCE helper.

- **Catalogue** = data: `catalog/connectors/<slug>/<version>.json` (seed set written for PasaBot: GitHub (official server in Docker), GitHub hosted (HTTP), files in a folder, git, time, Google Calendar sign-in; no raw web fetcher, because a stdio server does its own HTTP outside safe-net), plus `$PASABOT_CONNECTORS_CATALOG` (path list) and `$PASABOT_HOME/modules/connectors/catalog`. `src/manifest.ts` validates every file (strict schema; folder = slug, file = version; `{{secret:x}}` must name a secret field or `oauth_token` and only in env/headers, never args or the URL; `{{field:x}}` a plain field; http(s) URLs only; `uvx`/`npx`/`docker` launchers must name an exact release (`pkg==x`, `pkg@x.y.z`, `image@sha256:…`), `pipx` and `pnpm`/`yarn dlx` are refused; an `mcp-stdio` manifest takes no `network` section). Invalid files are skipped and logged once.
- **Installs** (`connectors_install`): plain field values in `config`, secret fields in the vault (`connectors/<install>/<key>`). An MCP-kind install is published as `connectors.mcp` (vault refs only) and the mcp module turns it into a server.
- **OAuth2 PKCE**: the owner gives the client id (and optional secret). `POST /installs/:id/oauth/start` returns the authorize URL (S256 challenge, single-use state, 10 min); the IdP returns to the public hook `GET /hooks/connectors/oauth/callback` (rate limited), which exchanges the code through safe-net (manifest `network.allowHosts`), stores the tokens in the vault and redirects to `/#/connectors?oauth=<outcome>`. Refresh: `POST /installs/:id/oauth/refresh`, and in the background for tokens expiring within 10 min; the vault ref stays the same.
- **On this computer** (W18, `src/detect.ts`): each catalogue entry gets one `state` (`added`, `ready`, `needs_key`, `missing` + what is missing and its official site). The launcher is looked up on PATH (never run) and Docker/Podman also by their app folder; nothing is downloaded; answers are cached for 30 s. `$PASABOT_CONNECTORS_PATH` / `$PASABOT_CONNECTORS_APPS` replace the PATH and apps folders (tests).
- **Found on this computer** (W18, `src/found.ts`): `GET /found` lists tool servers set up in Claude Code (`~/.claude.json`), the Claude app, Codex (`~/.codex/config.toml`) and OpenCode (`~/.config/opencode/opencode.json[c]`) by name, key names and transport only. `POST /found` imports one as an install (`found:<app>:<name>`): every env and header value goes straight to the vault and the mcp module gets refs only; one whose command line or address seems to carry a key (a `--token`/`--key` flag, a `--header`/`-H` value, a header line, an address with a user part, a token-shaped value) is refused (`add_by_hand`), and so is one whose command is a shell, a downloader, inline code or a program in a temporary or downloads folder. Each listed item carries `fp`, a per-process keyed fingerprint of its whole spec; `POST /found` must send it back and gets `409 changed` when the re-read file says something else. An imported server is created switched off: the owner turns it on on the MCP servers page. `$PASABOT_CONNECTORS_SCAN_HOME` replaces the home folder (tests).
- **Everyday apps** (W36, `src/discover.ts`): a manifest with `auth.oauth: { discover: 'mcp', clientIdFrom: 'register' }` signs in at the MCP server's own pages: `oauth/start` reads its RFC 9728 protected-resource metadata (else the server's origin), the RFC 8414 authorization-server metadata (S256 required), registers PasaBot once per return address (RFC 7591, public client) and sends the RFC 8707 `resource` with the authorize and token requests. Every request goes through safe-net with the manifest's `allowHosts` only; the pages the browser opens must be https. A catalogue add (not a found server) is usable by the main helper only (`useBy` on `connectors.mcp`), and posts a `connectors.connected` card in the main helper's chat. Manifests may carry `source`, `group`, `popular` and `auth.keyPage`. The list and its sources: `docs/CONNECTORS.md`.
- **REST** (owner session): `GET /catalog`, `GET/POST /installs`, `DELETE /installs/:id`, `GET/POST /found`, the two OAuth routes above.
- **Web**: `/connectors` (catalogue, install with write-only secrets, return address to register, sign in, remove).

Tests: `pnpm vitest run modules/connectors` (every catalogue file validates; GitHub install → MCP server with no token in any row or event; a stdio connector reaches an agent; full PKCE sign-in, single-use state, refresh and a refused wrong client against a local mock IdP + mock HTTP MCP server).

Known limits: `oauth-api` connectors (Google Calendar) store a token but no agent tool uses it yet; vault entries of a removed install are not deleted (no vault delete port); manifest labels are English data.
