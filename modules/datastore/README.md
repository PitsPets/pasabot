# `datastore` — shared SQL datastore (W11)

One SQL database every agent can use. Any agent lists the tables, makes new ones, reads and writes rows; only the
agent that made a table may alter or drop it. The owner browses it on the Data screen.

| Piece      | Here                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| file       | `$PASABOT_HOME/modules/datastore/datastore.db` (SQLite, WAL), separate from `pasabot.db`, inside `$PASABOT_HOME` so the runner sandbox denies agents direct access; capped at 256 MiB (`max_page_count`)                                                                                                                                                                                                                                                                                                                                                                             |
| metadata   | `datastore_table`(name NOCASE, owner_agent_id, created_at) in pasabot.db: who made each table                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| tools      | `datastore_list_tables` (0: DDL, columns, row count, creator, `you`), `datastore_query` (0: one read-only statement, 200 rows by default, 1000 max, ~1 MB), `datastore_create_table` (1), `datastore_write` (`params` or batched `rows` up to 20 000 in one transaction), `datastore_alter_table`, `datastore_drop_table`                                                                                                                                                                                                                                                            |
| tiers      | own table: write 1, alter 1, drop column 3, drop table 3; another agent's table: insert/update/upsert 2, delete and REPLACE conflict resolution (REPLACE INTO, INSERT/UPDATE OR REPLACE: deletes the rows it collides with) 3, alter/drop refused (tier 0, never asks the owner about a call that is refused anyway); the handler re-decides and refuses a call whose table changed hands while it waited; a no-op CREATE TABLE IF NOT EXISTS never changes a table's creator                                                                                                        |
| gate       | `src/sql.ts`: a hand-written linear tokenizer (no regular expressions). Refuses ATTACH, DETACH, PRAGMA, VACUUM, ANALYZE, REINDEX, LOAD_EXTENSION anywhere outside strings/quoted names, more than one statement, `sqlite_*` names, `schema.` prefixes, TEMP tables, views, triggers and indexes                                                                                                                                                                                                                                                                                      |
| worker     | `worker/sql-worker.mjs` holds the connection in a child process (not a worker thread: a statement spinning inside one native `sqlite3_step` ignores `Worker.terminate()`): one statement per prepare (better-sqlite3 refuses more), SQLite's `readonly` flag checked for queries, `trusted_schema=OFF`, `foreign_keys=OFF` (a REFERENCES from one agent's table must not pin another's rows); a call past 5 s SIGKILLs the process (its locks go with it) and the next call starts a fresh one; an idle process closes after 30 s; CREATE TABLE checks, caps and creates in one step |
| owner REST | `GET /api/m/datastore/tables` (tables + size), `GET /tables/:name/rows?limit=&offset=`, `POST /query` (read-only) — owner session only                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| redaction  | every string cell, column name and DDL passes `ModuleHost.redact` (7.3) on the way out of tools and REST                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| web        | Data screen `#/data` (nav item): tables with creator, row count and CREATE statement, first 50 rows, a read-only query box                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| locale     | `locales/en.json`, `locales/fil.json` (namespace `datastore`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

Rows written by one agent and read by another are data, never instructions (the tool descriptions say so).

Proof:

- `vitest run modules/datastore`: the gate (`src/sql.test.ts`) and the tools over `/mcp` on a booted server
  (`src/datastore.test.ts`): agent B's DROP on A's table refused by every road without an approval card; ATTACH,
  PRAGMA and multi-statement refused on every tool; a 10 000-row insert in one call under 1 s (about 30 ms); a
  runaway recursive query stopped at the time limit; tiers and approvals; owner-only REST; secrets redacted.
- `pnpm --filter @pasabot/web exec vite build && pnpm --filter @pasabot/mod-datastore test:e2e`: an agent makes a
  table and writes rows (probe brain), the owner opens Data from the nav, sees creator/rows/DDL, opens the rows,
  runs a query, a DELETE in the query box is refused (1440 and 390 px, no side scroll, 44 px button, FIL).

Not in v1 of this module: indexes and views (refused by the gate), owner edits or drops from the Data screen,
an export, per-agent quotas (the cap is store-wide).
