# `memory` — agent memory (W10) and the shared memory pool (W33)

Agents save short facts and find them later; the owner views, edits, forgets and merges them.

| Piece       | Here                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| tools       | `memory_remember` (tier 1 own on an owner turn; tier 2 for global/team or any non-owner turn), `memory_search` (tier 0: own + global + its teams; a turn the owner did not start gets only items saved during turns of its own kind of sender, never the owner's), `memory_teams` (tier 0), `memory_forget` (tier 3: delete data, 7.1)                                                                                                                                                                        |
| scopes      | **private** (one agent), **global** (`shared: true` / `scope: "global"`, every agent), **team** (`team: <name>`, a named group the owner makes). The backend sees them as `agentId`: the agent id, `null`, or `team-<id>` (kept to `[A-Za-z0-9_-]`, which plugin backends require). An agent writes only to scopes it belongs to                                                                                                                                                                              |
| provenance  | `memory_meta`: writer (owner / agent id / import), the turn's effective trust (never higher than the turn), time, key, confidence; set by the server, never taken from the tool input                                                                                                                                                                                                                                                                                                                         |
| conflicts   | same `key` in one scope: the newer value supersedes the older (it is forgotten in the backend) only when the owner writes it or the same writer writes it at no lower trust; a value that would replace the owner's, another writer's or a higher-trust entry waits in `memory_merge` (`reason: protected`), and so do two differing **high**-confidence values (`reason: conflict`); queued values are in no backend until the owner keeps one or writes the merged text. Writes to one scope are serialised |
| prompt      | `ModuleHost.prompt` contributor: on owner turns with tools, the top 8 hits for the user text go into the prompt only as the server-rendered `<untrusted-data source="memory">` block (quoted JSON strings, scope / writer / trust / confidence as meta)                                                                                                                                                                                                                                                       |
| delete      | owner delete (or edit, which replaces) forgets the entry in the active backend (local or a plugin) and marks its meta `deleted`; resolving a merge clears the dropped text; deleting a team deletes its entries; the W32 export never includes a deleted entry                                                                                                                                                                                                                                                |
| export port | `ModuleHost.memory.pool()` (`exportAgent` / `importAgent`, the host checks the actor: owner user or `asSystem`): the agent's private entries; import writes as `import` with trust lowered to `maxTrust`, all or nothing (entries validated first, an unknown trust level refused, capacity checked for the whole batch, a failure part-way removes what was written)                                                                                                                                         |
| limits      | per agent 500, shared 1000 (also per team), 2000 characters, 8 tags, 20 hits per search (owner can lower them: `PUT /settings`)                                                                                                                                                                                                                                                                                                                                                                               |
| backend     | `local` (table `memory_item` + FTS5 `memory_fts`) registered in `ModuleHost.memory`; plugins add more (`plugins/hindsight`). No cloud sync: nothing leaves the server unless the owner picks a remote backend                                                                                                                                                                                                                                                                                                 |
| owner REST  | `GET/PUT /settings`, `GET /items?scope=all\|shared\|<agentId>\|team-<id>&q=&origin=&offset=&limit=`, `PUT /items/:id` (edit), `DELETE /items/:id`, `POST /items/:id/reviewed` (local only), `GET/POST /teams`, `PUT/DELETE /teams/:id`, `GET /merges`, `POST /merges/:id`                                                                                                                                                                                                                                     |
| redaction   | text and tags pass `ModuleHost.redact` (7.3) before any backend gets them, and again on the way out of tools, REST and the prompt                                                                                                                                                                                                                                                                                                                                                                             |
| web         | memory page `#/memory` (scope + team filter, provenance and confidence per item, inline edit, merge queue cards, teams with a member picker), backend picker in Settings                                                                                                                                                                                                                                                                                                                                      |
| locale      | `locales/en.json`, `locales/fil.json` (namespace `memory`)                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

The active backend is picked per call; when the picked one is missing (plugin removed) the tools answer
"backend not available" instead of silently writing somewhere else. A forgotten local item keeps its row with
`forgotten_at` set but loses its text and tags and leaves the search index.

Proof: `vitest run modules/memory` — `runMemoryContract('local')`, tools over `/mcp` (scope, tiers, approvals,
limits, owner-only REST), `src/review.test.tsx`, and `src/pool.test.ts` (W33: team/global/private reads, a refused
write, merge queue vs supersede, the prompt block through a real turn, owner delete in local + a fake plugin backend +
the export, server-set provenance, edit, teams, the actor-checked export port). Playwright:
`apps/web/e2e/memory-pool.spec.ts` (1440 + 390, en + fil).
