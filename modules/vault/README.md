# `vault` — Settings → Vault, password managers, agent key requests (W14)

The owner's view of the secrets vault (ARCHITECTURE 7.3). Values never leave the server: agents get references
like `{{secret:NAME}}`, the panel only ever writes values, and every outbound text passes the redaction filter.

| Piece            | Here                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| grants           | a secret granted to an agent is an entry in scope `agent:<id>`; tool handlers resolve `{{secret:NAME}}` through `ToolCtx.vault` (the run's own agent scope only, audited as `vault.read`). `global` entries belong to the server, never to an agent                                                                                                                                                                                                                                                                                                                                                 |
| tools            | `vault_request_secret` (tier 1: asks the owner for a key by name + reason; deduped per name, at most 10 open per agent; returns the reference), `vault_list_secrets` (tier 0: granted references + open requests, never values)                                                                                                                                                                                                                                                                                                                                                                     |
| request flow     | request → owner notified → Settings → Vault card → fill with a value or a Bitwarden/1Password reference (or decline) → the entry is saved in `agent:<id>` and a system line in the requesting chat names the reference. A request caused by a non-owner turn is marked as possibly a lure                                                                                                                                                                                                                                                                                                           |
| backends         | `bitwarden` (`bw get item <id>` / `<id>/<field>`: password, username, notes, totp, custom field) and `1password` (`op read op://vault/item/field`), read-only; spawned with argv only and a scrubbed env; the session key / service-account token lives in the vault (`module:vault`)                                                                                                                                                                                                                                                                                                               |
| CLI binaries     | `PASABOT_BW_BIN` / `PASABOT_OP_BIN` (an absolute path; default `bw` / `op` in `/usr/local/bin`, `/opt/homebrew/bin`, `/usr/bin`, `/bin`, never the server's PATH): set by the operator, never from the web. Pinned once at boot to the real path; a backend is turned off (Settings → Vault says so, `state: unsafe_bin`) when that file or any folder above it can be changed by the server's OS user, since in host runner mode an agent CLI runs as that user. The child gets PATH = the binary's folder + `/usr/bin:/bin`, so a Node-script CLI needs an absolute shebang or a standalone build |
| rotation         | `POST /rotate { confirm: true }`: the only key rotation in the product; a new data key, every local secret re-encrypted, the key re-wrapped (one transaction)                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| owner REST       | `GET /api/m/vault/overview`, `POST /secrets`, `DELETE /secrets/:id` (global/agent entries only), `PUT /backends/:id/session`, `POST /backends/:id/test`, `POST /requests/:id/fill`, `POST /requests/:id/decline`, `POST /rotate`: owner session only                                                                                                                                                                                                                                                                                                                                                |
| redaction (core) | known values plus their JSON-escaped, URL-encoded and base64 forms; backend values once fetched; a streamed reply holds back a tail that could start a secret, of any length, and any unterminated token shape (`Redact.stream`)                                                                                                                                                                                                                                                                                                                                                                    |
| web              | Settings → Vault (`settingsSections`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| locale           | `locales/en.json`, `locales/fil.json` (namespace `vault`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
