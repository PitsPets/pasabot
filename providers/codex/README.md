# @pasabot/provider-codex

`ProviderAdapter` for the Codex CLI (`codex exec --json`, one process per turn, prompt on stdin).

- Maps the JSONL stream to ProviderEvents: `thread.started` → session, reasoning → thinking, each agent message → one text delta (exec mode prints whole messages, not tokens), shell / MCP / file-change / web-search items → tool call + result, `turn.completed` → final text + usage (cached tokens split out of input), `turn.failed` → classified error with the reset time when the CLI states one. Exactly one `done`.
- Resume: `codex exec resume <thread id> -`. The system prompt goes in as Codex developer instructions (`-c developer_instructions=…`) on every turn, resumed ones included, so an edited instruction reaches existing chats; it never shares the user message with untrusted text. A reseed, when given, goes ahead of the user text in a new session as an `<earlier-conversation>` block; wrapper tag names inside untrusted text (user text, summary, message bodies) are defused (`<` → `&lt;`) so they cannot close or forge a block (ARCHITECTURE 8).
- MCP: the PasaBot gateway is added with `-c mcp_servers.pasabot.*`; the run bearer travels in the `PASABOT_MCP_TOKEN` env var (never argv) and is excluded from the agent's shell env. `--ignore-user-config` keeps the owner's own `~/.codex/config.toml` (personal MCP servers, profiles) away from agents; login still comes from `$CODEX_HOME`.
- No permission bridge in exec mode. The turn's **effective** trust maps to Codex's own sandbox: the lower of the agent's and the sender's trust, one level lower for any sender but the owner (ARCHITECTURE 7.1, 7.4; same rule as the approvals service), so a non-owner turn is never `trusted`. `workspace-write` at every level, network only for `trusted`, never `danger-full-access`; approval policy `never`. Tool-less calls (`tools: 'none'`) run `read-only` without the gateway.
- Runner sandbox: every spawn goes through `TurnInput.sandbox` with `$CODEX_HOME` (else `~/.codex`) writable. **Documented exception (macOS only):** macOS refuses to nest Codex's Seatbelt inside PasaBot's (`sandbox_apply: Operation not permitted`), so under an outer sandbox a `trusted` owner turn runs with `--dangerously-bypass-approvals-and-sandbox` and the runner sandbox is the only boundary: Codex's workspace-only write limit is lost there, so tier 3 (writes outside the workspace) is not asked for that case. Every other platform keeps `--sandbox workspace-write` under the runner sandbox; lower levels keep Codex's sandbox everywhere, so their shell commands fail in macOS host mode.
- A provider account sets `CODEX_HOME` to its config dir.
- `steer` is not offered: exec mode reads the prompt once. `skillsDir` = `<workspace>/.codex/skills`.

Tests replay a recorded-format stream (`src/__fixtures__/stream.jsonl`) through a stand-in CLI, so they need no network or account. Live run on a developer machine: `PASABOT_LIVE=codex pnpm test:live`.
