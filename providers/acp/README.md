# @pasabot/provider-acp

Generic `ProviderAdapter` for any CLI that speaks the **Agent Client Protocol** (JSON-RPC 2.0 over stdio, one object per line). A library, not a discovered provider: Gemini and Grok are profiles over it, and the `acp-registry` module registers one instance per installed agent as `acp:<id>`.

- One process per turn: `initialize` (no `fs` / `terminal` client capability is offered, so those agent requests are refused with -32601) → `session/load` when the agent offers `loadSession` and a native ref is given (updates replayed by the load are dropped) or `session/new` → `session/prompt`.
- Mapping: `agent_message_chunk` → text delta, `agent_thought_chunk` → thinking, `tool_call` / `tool_call_update` (completed/failed) → tool call / result, stop reason `end_turn` / `max_tokens` → final text + `usage` when the response carries one, `cancelled` → cancelled done, `refusal` → error. A JSON-RPC error is classified (rate limit with reset time, quota, auth — ACP's -32000 "auth required" is `auth` — context, timeout, crash); a dead process reports its stderr tail. Exactly one `done`.
- Prompt: ACP has no system-prompt field, so a new session starts with `<instructions>` (trusted PasaBot text), then the reseed as `<earlier-conversation>`, then the user text; wrapper tag names in untrusted text are defused. A resumed session gets the `<instructions>` block again on every turn, then the user text (never the reseed): an edited instruction reaches existing chats, and the untrusted-data preamble survives the CLI compressing its own history.
- MCP: the PasaBot gateway is passed as an HTTP MCP server with `Authorization: Bearer <run token>` as a header, never in argv or env; only when the agent declares `mcpCapabilities.http` and the turn has tools. An agent without HTTP MCP gets no gateway tools.
- Permission bridge: `session/request_permission` → a `permission` event. Tiering input (ARCHITECTURE 7.1): a call to the gateway's own server (kind `other` or none, and a whole title of the form `<tool> (pasabot MCP Server)`, `mcp__pasabot__<tool>`, `pasabot__<tool>` or `pasabot.<tool>`, tool name `[A-Za-z0-9_-]`, only on turns that handed the agent the gateway) → `mcp__pasabot__<tool>`, tier 0 here and tiered again by the gateway at `tools/call`, as with the Claude adapter; `read`/`search` → `Read`, `edit`/`delete`/`move` → `Write`, with the location most likely to leave the workspace (lexical or real path); a write with no location tiers as outside the workspace (3), a read with no location and every other kind (`execute`, `fetch`, …) as `acp.<kind>` (2). Allow picks `allow_once` only (never `allow_always`: one approval must not become a standing grant inside the agent); deny picks `reject_once`/`reject_always`; abort answers open requests `cancelled`.
- Abort: `session/cancel`, then the whole process group gets SIGTERM after ≤ 500 ms and SIGKILL after the grace. Every spawn goes through `TurnInput.sandbox` with the profile's state paths writable and its `readPaths` (a registry npm agent's install folder) readable.
- `detect`: `<cmd> --version` (or only a binary check when `versionArgs: null`, which registry agents always use); sign-in is `unknown` (ACP reports it on the first turn). `steer` is not offered (ACP has no mid-turn injection).

Tests drive a test ACP echo agent written for PasaBot (`src/__fixtures__/echo-agent.mjs`): `pnpm vitest run providers/acp`.
